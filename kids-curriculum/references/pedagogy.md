# Pedagogy — Differentiation, UDL, and Misconceptions

Read this reference when writing the **lesson plan** (specifically the Differentiation and Notes-for-Teacher sections) or when a unit touches a topic with a well-known misconception. The main SKILL.md keeps these as one-line rules; this file explains them so you can apply them with judgment instead of mechanically.

## Differentiation: teach-up, not water-down

There are three tiers per lesson: **Support / Core / Extension.** The core principle, borrowed from established K–12 practice, is that all three tiers aim at the *same grade-level objective*. You do not rescue struggling students by swapping in easier, lower-grade content — that widens the gap. You scaffold the grade-level task so they can reach it.

### The three tiers

| Tier | Who it's for | What you change | What you keep identical |
|---|---|---|---|
| **Support** | Students who would fail the Core set cold | Add 1–2 scaffolds (a visual model, a worked-example skeleton, a sentence frame, fewer problems, a math tool). Use a **fade pattern** — 2 scaffolds → 1 → 0 across the problem set so independence grows. | The **objective, the topic, and the final problem type.** A Support student should end the lesson working the same kind of problem as a Core student. |
| **Core** | On-level students | Nothing — this is the workbook set as written. | — |
| **Extension** | Students who finish Core correctly and fast | A task that requires *new thinking*, not more-of-the-same. (See the quality test below.) | The objective — it extends, doesn't escape. |

### How to route a Support student *up* to grade level

When a Grade 4 topic genuinely requires a Grade 3 prerequisite the student lacks, name the prerequisite and add one short bridge step — don't silently demote the whole lesson.

- Identify the named prerequisite (e.g., "multiplication as equal groups").
- Add a 2-minute bridge at the top of the Support version: a worked example + one practice item on the prerequisite.
- Then proceed to the grade-level objective with scaffolds.

This is "teach-up via named prerequisite." It is the opposite of handing the student a Grade 3 worksheet and calling it differentiation.

### Scaffold density rule

A single problem carries **at most 1–2 scaffolds.** More than that and the student is no longer doing the math/thinking — they're filling in a template. If you need 3+ scaffolds, the problem is too hard and should be split.

### The Extension quality test

Before accepting an Extension task, ask: **"What new thinking does this require?"** Reject and redo if the answer is:

- More of the same ("do 10 more problems")
- Notation swap ("write the answer as a decimal instead of a fraction")
- Bigger numbers without a new idea

Good extensions: a two-step problem where the lesson was one-step; an open-ended "make your own problem with this structure"; a transfer task ("where would you see this in the real world?").

### Invisible scaffolds

When you produce a Support-tier worksheet, never label it as such in student-facing language. No "(easier version)", no "(no organizer this time)", no star or remedial framing. The scaffolds are simply present. A student reading the page should not know it is "the help version." Equity requires this.

## UDL, treated as barrier analysis (not a checklist)

Universal Design for Learning is a *design framework*, not a checklist to tick. Use it as a lens: **what about this lesson might unintentionally shut a learner out?** For each lesson, scan for barriers in three areas. If you find one, add a concrete fix — and "use multiple representations" is not a fix, it's a slogan. A fix names the specific change.

- **Engagement (the *why*)** — Does the lesson recruit interest and sustain effort? *Barrier:* a dry abstract warm-up. *Fix:* open with a 30-second story, image, or question the kid actually cares about ("Would you rather have 1/3 of this pizza or 1/4?").
- **Representation (the *what*)** — Is the content presented in more than one way? *Barrier:* a wall of text explaining long division. *Fix:* a worked example shown as a labeled diagram **and** in numbers, side by side.
- **Action & Expression (the *how*)** — Can students show what they know in more than one way? *Barrier:* every problem is a written computation. *Fix:* include one problem that says "draw a model to show your answer" or "explain to a partner how you know."

For a 45-minute single lesson, **two or three concrete UDL fixes** is plenty. Don't force one per problem.

## Misconceptions — the heart of a good lesson plan

The single most useful thing in the teacher's lesson plan is a clear statement of the **anticipated misconception**: the wrong idea a reasonable student will form, and why it's wrong. This drives the exit ticket (it must catch the misconception) and the teacher's circulating questions.

Common high-value misconceptions for Grades 3–5:

**Math**
- Fractions: "bigger denominator means bigger fraction" (1/4 > 1/2 because 4 > 2). Fix: always return to the area model / number line.
- Multiplication: "multiplying always makes numbers bigger." Misleads with fractions and decimals. Fix: introduce 4 × 1/3 early.
- Long division: placing the digit in the wrong place-value column. Fix: keep the place-value chart visible.
- Equal sign: reading "=" as "the answer is" rather than "is the same as." Fix: write true/false equations like 3 + 4 = 5 + 2.

**English**
- Main idea: confusing the *topic* (one word: "sharks") with the *main idea* (a sentence: "sharks have adaptations that make them effective hunters"). Fix: require a full-sentence main idea.
- Summarizing: retelling every event (Grade 3 skill) instead of selecting the most important (Grade 4–5 skill). Fix: impose a word limit or a "3 most important events" cap.
- Evidence vs. inference: stating a claim with no quoted text support. Fix: require the sentence stem "On page __, the text says '...' which shows that..."
- Quotation marks in dialogue: placing them around the wrong span. Fix: model with highlighter which words are *spoken*.

### Anticipated-responses technique (from lesson study)

For each independent-practice problem, the lesson plan should briefly note **2–3 anticipated student responses** — including at least one wrong-but-informative one. This pre-arms the teacher to notice it while circulating. Example:

> *Problem 3 (find 1/3 of 9).* Anticipated responses: (a) 3 [correct], (b) 3 with a diagram of 3 groups of 3 [correct, strong], (c) 1/9 or "you can't" [student treating 1/3 × 9 as 9 ÷ 1/3 inverted — re-anchor on "of means ×"].

## Standards (lite)

This skill does not require a particular standards document. When the user cares about alignment (e.g., "is this Common Core Grade 4?"), the safest move is:

- Anchor to **Common Core State Standards (CCSS)** naming by default — it's the most widely recognized. Reference the cluster (e.g., "4.NF.A.1: Explain why a fraction a/b is equivalent…").
- If the user names another framework (TEKS, SOL, OAS, UK National Curriculum, IB PYP), use theirs.
- Never invent a standard code. If you're unsure of the exact code, name the cluster in plain language and offer to look up the code rather than fabricating one.

Caveat to pass to the user when relevant: alignment-by-skill is not the same as a formal crosswalk; a teacher should confirm against the official document. (This candor matters — overclaiming alignment erodes trust.)
